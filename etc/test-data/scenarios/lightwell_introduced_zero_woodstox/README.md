# lightwell_introduced_zero_woodstox — `introduced: "0"` is an open low bound

Snapshot: `lightwell-osv` @ `ae0cbae` (2026-11-13, 288 advisories). Rule: `--rule scoped`.
Encodes `docs/README.md` §3 (field table).

In OSV, `introduced: "0"` is the sentinel for "from the beginning of time", not the literal
version string `0`. 193 of the 288 snapshot records use it; the other 95 set `introduced` to the
`backport_base_version`. `introduced` is the one field the dataset actively migrates
(`check_ranges.py`'s `DEFAULT_ALLOWED`), which is why this scenario pins the snapshot commit.

`"0"` were compared as a literal version, `1.0.0 >= "0"` would still hold under Maven ordering, but
a comparator that treated `"0"` as an unparseable literal would drop it. The remediated build is
excluded by the exclusive `fixed` bound.

Expectations are generated by `tools/check_ranges.py`'s `in_range` + `comparator`, not by Trustify.
